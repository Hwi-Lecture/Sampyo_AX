# 3번 방법 — FastAPI + HTML/CSS/JS (PPT 122p)

같은 날씨 대시보드를 **FastAPI 백엔드 + HTML 프론트엔드** 구조로 만든 완성
예시입니다. (별도 다단계 실습이 아니라, 이론 설명 중 보여주는 완성본입니다.)

## 구조

```
backend.py        API 호출 + 데이터 가공만 담당 (백엔드)
static/index.html 화면만 담당 — fetch()로 backend에 데이터 요청 (프론트엔드)
```

1_python_html이 "파이썬이 파일(js)을 만들어 두면 화면이 그 파일을 읽는"
방식이라면, 이 폴더는 "화면이 필요할 때마다 서버에 실시간으로 데이터를
요청(API 통신)"하는 방식입니다. 그래서 새로고침만 하면 항상 최신 데이터를
받아옵니다(파이썬을 따로 다시 실행할 필요가 없음).

## 실행 방법

```
pip install fastapi uvicorn requests
uvicorn backend:app --reload --port 8000
```

브라우저에서 http://localhost:8000 접속 → 화면이 내부적으로
http://localhost:8000/api/weather 를 호출해서 데이터를 채웁니다.

## 1_python_html / 2_streamlit과 비교 포인트

| | 1_python_html | 2_streamlit | 3_fastapi |
|---|---|---|---|
| 데이터를 넘기는 방식 | 파일(weather_data.js) | (파일 없음, 코드 내부에서 바로) | API 요청/응답(JSON) |
| 새로고침하면 | 예전 데이터 그대로 (파이썬 재실행 필요) | 최신 데이터 (캐시 만료 전까지는 동일) | 매번 최신 데이터 |
| 화면 자유도 | 높음 (CSS 직접 작성) | 낮음 (Streamlit 위젯 범위) | 높음 (CSS 직접 작성) |
| 구현 난이도 | 낮음 | 낮음 | 높음 (백엔드/프론트 분리, 서버 개념 필요) |
| 계속 보려면 | 서버 불필요 | 서버 필요 | 서버 필요 |

  분석·시각화까지 유기적으로 연결됨. UI 커스터마이징도 자유로움.
- 단점: 구현이 복잡하고 서버를 띄워서 확인해야 함.
